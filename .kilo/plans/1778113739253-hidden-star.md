# Fix: Stats Don't Sync + Upgrades Don't Apply for Client

## Bug
1. The client's stat panel (GameHud.razor) shows incorrect/outdated stats
2. When the client selects an upgrade, their damage/fire-rate doesn't change

## Root Cause
Same root cause for both: `SelectUpgrade` / `SelectPlaystyle` are `[Rpc.Host]` on a client-owned UM. These may run on the **host** (authoritative copy) but the **client's local copy** of `CurrentUpgrades` isn't updated until `[Sync]` eventually replicates.

The client's ArrowPlayer reads stats from `_um.CurrentUpgrades` — the local copy. If the upgrade was only applied on the host's authoritative copy, the client's gameplay and UI don't see the change.

## Fix: Convert SelectUpgrade/SelectPlaystyle to Broadcast Pattern

Use the SAME pattern that already works for `HasSelected` (via `BroadcastSelection()`): when the client clicks, the upgrade applies **immediately locally** AND **broadcasts to the host** for authority.

### Changes

#### 1. `UpgradeManager.cs` — Convert SelectUpgrade and SelectPlaystyle

Replace the current `[Rpc.Host]` methods with a two-method pattern:

```csharp
// Public method called from Razor panel — runs locally on the caller
public void SelectUpgrade( UpgradeType type )
{
    if ( HasSelected ) return;
    BroadcastSelectUpgrade( type );
}

[Broadcast]
public void BroadcastSelectUpgrade( UpgradeType type )
{
    if ( HasSelected ) return;
    var state = CurrentUpgrades ?? new UpgradeState();
    state.ApplyUpgrade( type );
    CurrentUpgrades = state;
    LastSelected = type;
    HasSelected = true;
    ApplyUpgradeEffect( type );
    CheckAllReady();
}

public void SelectPlaystyle( Playstyle ps )
{
    if ( HasSelected ) return;
    BroadcastSelectPlaystyle( ps );
}

[Broadcast]
public void BroadcastSelectPlaystyle( Playstyle ps )
{
    if ( HasSelected ) return;
    var state = CurrentUpgrades ?? new UpgradeState();
    state.ChosenPlaystyle = ps;
    state.PlaystyleLocked = true;
    CurrentUpgrades = state;
    HasSelected = true;
    PlaystyleSelected = true;
    CheckAllReady();
}
```

#### 2. `UpgradeManager.cs` — Remove `BroadcastSelection()`

The `SelectUpgrade`/`SelectPlaystyle` methods no longer call `BroadcastSelection()` because the new `[Broadcast]` methods already include `HasSelected = true`. Delete `BroadcastSelection()` method and all 3 call sites.

#### 3. `UpgradeManager.cs` — Fix `OfferUpgrades()` empty-pool case

```csharp
if ( pool.Count == 0 )
{
    HasSelected = true;
    // Remove BroadcastSelection() call
    return;
}
```

### Flow After Fix

```
Client clicks card → um.SelectUpgrade(option) → runs locally
    → BroadcastSelectUpgrade(option) → [Broadcast] to ALL including host
        → Client: CurrentUpgrades updated → stats update → gameplay changes ✓
        → Host:  CurrentUpgrades updated on authoritative copy
        → Host:  HasSelected = true, CheckAllReady() runs
```
